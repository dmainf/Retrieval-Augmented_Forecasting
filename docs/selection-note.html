文脈が似ていても未来は似ない，を測る

既存の RAF の核にある問題は「文脈が似た窓を選んでも，その未来はクエリの未来に似ていない」ことである． これを 3 つの方向から調べた．読み手（Chronos-2）が見ている座標で選ぶ， 事例の文脈を 96 点より長くする，読み手の attention に選ばせる． 分かった一番大きなことは，未来が似た窓を選んでも，それがモデル自身の予測と同じ情報なら効かないことである． 効き目を決めるのは，未来の近さではなく，モデルの誤差についてどれだけ情報を運ぶかである．

問いと先行研究

これまでのノートで，未来照合（正解に未来が近い窓，診断）は 8 件で MSE −11.1% なのに， 文脈照合（従来の RAF）は 8 件で −1.3%，最良でも 64 件で −3.2% にとどまることが分かっていた． この差の原因は「文脈が似た窓の未来が似ていない」ことにある．先行研究での位置は次のとおり．

論点先行研究このノートとの関係
文脈と未来の類似のずれ SARAF（arXiv 2606.04135）：非定常なデータで相関が弱い（Exchange で Spearman 0.285）．多様性で対処 同じ現象．ここでは「読み手の座標」で測ると相関がどう変わるかを見る（2 節）
未来で教師付けした検索器 PRR（arXiv 2608.23221）：実現した未来との相性を学習時の教師にした reranker．TimeRAF：予測誤差の減り方で retriever を学習 5 節の結果は，「未来との相性」を目標にすること自体の限界を示す
many-shot での選び方 Baek et al.（arXiv 2412.16926）：18 データセットで，凝った選び方はランダムに勝てない CLG の結果（別冊）と一致
attention で選ぶ ICR（Chen et al., ICLR 2025）：LLM の attention で文書を再順位付け．中身のないクエリで補正． WICL（Findings of EMNLP 2023）：attention を重み付けして事例を重み付け． Data Whisperer（arXiv 2505.12212）：attention で微調整データを選ぶ． TabPFN v2 の最終層の attention が暗黙の検索になっている，という分析（arXiv 2506.08982） 時系列の基盤モデルで group attention を使って事例を選ぶ例は見つからなかった（6 節）
出典の確認度 PRR，SARAF，Data Whisperer はアブストラクトと検索結果の抜粋で確認した．本文は未確認．

読み手が見ている座標

並列では，各行が自分の文脈だけで instance norm される（平均を引き，標準偏差で割り，arcsinh をかける）． 事例の行は事例の文脈 L 点で，クエリの行は履歴 2032 点で正規化される． したがって読み手には事例の絶対的な水準が見えない．見えるのは「その窓の中で，文脈に比べて未来がどう動いたか」だけである． 一方，従来の文脈照合は生の値の L2 で選ぶので，水準の近さで選んでいる．

そこで，モデルを使わずに，候補の窓の未来がクエリの未来にどれだけ近いかを読み手の座標で測った． 指標は 2 つである．文脈の距離と未来の距離の順位相関（クエリごとに候補全体で計算して平均）と， 文脈で選んだ上位 8 件の未来の距離が「ランダム → 未来で選んだ最良 8 件」の差をどれだけ埋めるか（1 なら未来照合と同じ）．

今の設定（96 点，生の L2）は，読み手の座標で見ると未来の近さとほぼ無関係である（順位相関 +0.07，差の 8%）． ノートの整理前の測定（OT で +0.12）と同じ程度である． 読み手と同じ座標で比べるだけで，差の 37% まで埋まる．文脈を長くすると，どちらの検索も良くなる． また，生の値の未来照合ですら，読み手の座標では差の 55% しか埋めていない．

ただし

この「未来の近さ」は予測の改善とは一致しなかった（4 節，5 節）．この表は検索の質の目安にすぎない．

分かったこと

文脈を長くすると，読み手は事例をより強く信じる．正しい事例ならより効き（oraclerv は 96 点 −12.0% → 384 点 −15.9%）， 外れた事例ならより害になる（l2 は 96 点 −1.3% → 768 点 +9.1%）． 2 節のとおり文脈を長くすると検索の質（未来の近さ）は上がるのに，K=8 の文脈照合はかえって悪くなる．検索の質の上がり方より，信じ方の強まり方が大きい． 件数が多いと（K=128），外れた事例の害が平均でならされるためか，192 点で良くなった．

したがって長い文脈は，選び方が良ければ伸びしろを広げ，悪ければ害を増やす．選び方の問題がより重要になる．

文脈長と連動して変わるハイパーパラメータ

  • 候補の除外条件（対処済み）：以前は「窓がクエリの文脈の始まりより前に終わる」で，文脈長と連動して除外が増えていた． 「予測の起点より 96 点以上前に終わる」に固定した（run.py の GAP）．96 点では以前と同じ窓が選ばれ，予測も一致することを確認した（差 8e-6）．
  • 検索キーの長さ（未分離）：l2 は事例の文脈全体を比べるので，キーの長さも一緒に変わっている．「読み手に渡す長さ」と「検索に使う長さ」は分けていない．
  • 候補の数：train 12 か月から切るので，1536 点では 771 本 → 640 本に減る．
  • 計算量：事例 1 件のトークンは 11 → 17 / 29 / 53 / 101．K=128 は 768 点で 1 チャネル 42 秒 → 176 秒（実測）．同じ計算量なら K を減らす必要がある．
  • 正規化：事例の行は L 点で正規化されるので，長いほどクエリ（2032 点）の正規化に近づく．2 節で生の L2 と読み手の座標の差が縮むのはこのため．
  • 候補の間隔（未対処）：11 点ずらしの隣の候補との重なりは，96 点で 93%，1536 点で 99% になる．もともと重なりは大きいが，長いほど上位 K が同じような窓ばかりになりやすい．
  • K の最適値：文脈長で変わる（K=8 と K=128 で向きが逆）．val で選び直す必要がある．
  • 上限：事例の文脈は履歴（2032 点）より長くできない．
5

未来が似ているだけでは効かない

2 節と 4 節で，「未来の近さ」が上がっても予測が良くならない例が出た．そこで，未来照合の目標を正解からずらして，効き目がどう変わるかを測った． 目標は y+λ(y^−y) で， y は正解，y^ は参照なしの中央値の予測である． λ=0 は今の未来照合，λ=1 は「モデルの予測に未来が近い窓」を選ぶことになり，正解を使わないので実際に使える（HyDE 型，予測してから検索）．

分かったこと

参照なしの予測に未来が近い窓（λ=1）は，生の値でも読み手の座標でも，文脈照合より未来が近い．それなのに効果はゼロである． 効き目は λ に対してほぼ直線的に減る．つまり，未来照合が効くのは「未来が似た窓だから」ではなく， モデルの予測が外れている分（y−y^）の情報を事例が運んでいるからである． モデルがすでに予測している未来を事例で見せても，確認になるだけで何も足さない（エコー）．

コアの問題の言い直し

「文脈が似ていても未来は似ない」は半分しか正しくない．仮に未来が似た窓を選べても，その似方がモデルの予測と同じなら効かない． 実際に使える検索が狙うべきなのは未来の近さではなく，モデルの誤差について情報を持つ窓である． PRR のように「未来との相性」を教師にする検索器は，この点で目標がずれている可能性がある．

ここから次の案が出る（未実施）．気象の analog ensemble と同じく，候補の窓にも参照なしの予測を出しておき，予測がクエリに似た窓を選んで，その窓の実際の未来を渡す． 「モデルがこう予測した状況で，実際には何が起きたか」を見せるので，事例がモデルの誤差の情報を運ぶ． 候補 771 本×7 チャネルに参照なしの予測を 1 回ずつ出すだけで試せる．

なぜ遠い窓に向くのか

全層平均の attention と，事例の未来の値の大きさ（読み手の座標での絶対値の平均）の順位相関は +0.60 だった． attention は未来の近さではなく，値が大きく振れる「目立つ行」に引かれている．これは関連度ではなく顕著さである． 最終層だけは値の大きさと無関係（+0.01）で，未来の近さと対応する．

LLM の ICR は同じ種類の偏りを，中身のないクエリで測った attention で補正している． 時系列版として，値が平らな履歴をクエリにしたときの attention で割ったが，どの層でも良くならなかった（全層平均 −1.47，最終層 −0.40）． 偏りがクエリごとに違うので，共通の基準では打ち消せないと考えられる．

位置づけ

attention をそのまま選び方に使うのは，時系列では失敗する．これは負の結果として書ける． TabPFN では最終層の attention が暗黙の検索になっているという報告があり，Chronos-2 でも最終層だけがそれに当たる． ただし予測は文脈照合に届かず，5 節のとおり「未来の近さ」を上げても効かないので，attention で選ぶ案の優先度は下げる．
