q，k，v の使い方で選ぶ

提案手法は，クエリの q0 と候補の k の内積で事例を選ぶ．ヘッドの出力を q，k，v で書き，q，k，v，qk，qkv のそれぞれを，全体・続きを見せる前の項（前項）・続きによる変化の項（変化項）の 3 通りにした 15 個の点数で，ヘッドを選び直した．そのうち 11 個で予測を流した．q と k の全体の点数は，選んだ事例の続きが，予測対象で選ぶ場合を除けば予測対象に最も近かったが，MSE は提案手法より大きかった（+0.80±0.55，+1.91±0.73 ポイント）．提案手法との MSE の差が標準誤差の 2 倍を超えて負になった点数はない．

1

ヘッドの出力を q，k，v で書く

提案手法は，選択ヘッド 3 本（L12H1，L11H10，L10H12）で，クエリの query q0 と候補の key kj の内積から求めた重みで，クエリごとに引いた候補 2048 件から 256 件を選ぶ（attention で選ぶ）．

Chronos-2 の group attention では，列ごとに，クエリの行が自分の行と事例の行の value を重みづけて足す．ヘッド 1 本，列 1 つについて，重みの和が 1 になることを使うと，ヘッドの出力 o は次のように書ける．

o−v0WO=∑j=1Nexp(q0·kj)exp(q0·k0)+∑i=1Nexp(q0·ki)(vj−v0)WO

q0，k0，v0 はクエリの query，key，value，qj，kj，vj は候補 j の query，key，value，N は候補の数，WO は出力の射影である．Chronos-2 は q0·kj を √dk で割らない．分母は全候補で共通なので，候補 j の分は exp(q0·kj)(vj − v0)WO に比例する．候補 j の分を決めるのは q0·kj と vj − v0 で，候補自身の qj は使われない．

点数に使う q，k，v は，クエリと候補を 1 本ずつ単独で流して前計算したもので（提案手法の (D)），事例を並べて流したときの値とは一致しない．候補は train の窓で続きが分かっているので，同じ候補を，続きを入れた場合と隠した場合の 2 通りに流す．

候補を 2 通りに流す続きを隠すとは，クエリと同じく，4 つの予測パッチを欠測として入れること．続きを隠して流したときのベクトルには ~ を付けて q̃j，k̃j，ṽj と書く．どのベクトルも予測パッチ 4 列で取り，窓ごとに 1 回の前計算で求まる．クエリには続きがないので，q0，k0，v0 は続きを隠したものだけである．

2 通りの値を使うと，候補とクエリの差は，q，k，v のどれでも，続きを見せる前の項（前項）と，続きを見せたことによる変化の項（変化項）に分かれる．q0 と k の内積も同じように分かれる．v は WO を掛けたヘッドの出力の空間で測る．

xj−x0=(x~j−x0)⏟前項+(xj−x~j)⏟変化項,x∈{q,k,v}q0·kj=q0·k~j⏟前項+q0·(kj−k~j)⏟変化項
前項と変化項に分ける左は q0 と k の内積の数直線，右はヘッドの出力の空間（v に WO を掛けたもの）の模式図（ヘッド 1 本，予測パッチ 1 つ）．灰は前項，橙は変化項，破線は続きを入れた全体．左はスカラーの和で，足すと q0·kj になる．右はベクトルの和で，足すと vj − v0 になる．q と k の差も右と同じベクトルの和になる．

ṽj が v0 に近い候補では，vj − v0 はほぼ変化項 vj − ṽj だけになる．k̃j が k0 に近い候補では，q0·kj はほぼ q0·k0 + q0·(kj − k̃j) になる．どちらの場合も，候補の分は候補の続きによる変化だけで決まる．

2

予測を流した結果

ETTh1 の val の全起点（1162 クエリ）で予測を流した．どれも候補，件数，入れ方（並列の行，P1 を隠す）は同じで，点数とヘッドだけが違う．15 個の点数のうち予測を流したのは，前回までに流した 5 個（qk，qk 前項，qk 変化項，v 前項，v 変化項）と，今回加えた 6 個（q，q 前項，k，qkv の 3 つ）の 11 個である．2 行ある点数は，1 行目が点数ごとに選び直した 3 本で，2 行目が提案手法の 3 本に固定したもの．ヘッドは，codes/heads.py で点数ごとに選び直した．val の各チャネルに均等に散らばる 60 起点（計 420 クエリ）で train の窓 512 件を候補にし，候補の点数と，候補の続きがクエリの予測対象に近い順の順位相関をクエリで平均して，全 12 層の 144 ヘッドから相関の高い 3 本を選んだ．今回加えた q，q 前項，k は，予測を流していない点数のうち，選んだ 3 本の相関の平均が高いもの．下の「分かったこと」の提案手法との差は，MSE（MAE）の変化率の差（ポイント）で，± はチャネルごとに起点を 1000 回復元抽出した標準誤差．

点数ごとの結果（ETTh1，val，全起点 1162 クエリ）添字 0 はクエリ，j は候補，~ は続きを隠して流した値．‖·‖ は L2 ノルムで，Σ はヘッドと予測パッチ 4 列の和．s(·) は，列ごとにクエリ自身と候補の上で取った softmax（クエリ自身の項は q0·k0）．w(·) は s(·) を予測パッチ 4 列で平均し，ヘッドごとに候補の和が 1 になるようにそろえてから，ヘッドで平均したもの．式の下はオプション（codes/run.py --select attn の --value-score の値）．− は予測を流していない点数．事例の続きと予測対象の RMSE は，クエリごとに，選んだ 256 件それぞれの続き 64 時点（その事例の文脈 512 時点の平均と標準偏差で標準化）と，クエリの予測対象 64 時点（クエリの履歴の最後 512 時点の平均と標準偏差で標準化）の差の L2 ノルムを √64 で割った値を，256 件で平均し，全 1162 クエリで平均したもの．予測対象で選ぶ 256 件は，同じ候補 2048 件の中でこの値が小さい順の 256 件なので，その行の値（0.973）が取りうる最小値である．MSE と MAE は，参照なし（MSE 0.5383，MAE 0.4696）に対する変化率で，チャネルの平均．qk 全体の 2 行目は，提案手法の点数のままヘッドだけを選び直したもの．予測対象で選ぶは，クエリの予測対象を使って選ぶので手法ではない．

点数について

  • qk だけは，内積がそのまま数になる．q，k，v を単独で使うときは，差の L2 ノルムで数にする．
  • qkv はベクトル s(q0·kj)(vj − v0)WO なので，L2 ノルムを取ると，候補がヘッドの出力を動かす量の大きさになる．向きは使わない．
  • q，k，v の変化項は，クエリを使わない．どのクエリでも候補の並びが同じになるので，大きい順と小さい順の両方を点数にした．
  • q，k，v の全体の点数は，続きを入れた候補と，続きを隠したクエリを比べる．
  • qj は 1 節の式に出てこない．q だけの点数は，ヘッドの出力の計算には使われないベクトルの近さである．
  • qk の重みを v 前項の大きさで割る点数（qk ÷ v 前項）は，2 つの点数の組み合わせなので 15 個に入れず，qk と v を組み合わせて選ぶに書いた．

分かったこと

  • q と k の全体の点数は，事例の続きと予測対象の RMSE が予測対象で選ぶ場合を除いて表の中で最も小さかったが，MSE は提案手法より大きかった．RMSE は 1.196 と 1.200（提案手法は 1.283）．提案手法との差は q が +0.80±0.55，k が +1.91±0.73（標準誤差の 2.6 倍）．
  • q 前項は，提案手法との差が標準誤差の中だった．+0.39±0.68．
  • 提案手法との MSE の差が標準誤差の 2 倍を超えて負になった点数はない．差が最も負に大きかったのは qkv 前項（−0.58±0.62）．
  • 提案手法より MSE が標準誤差の 2 倍を超えて大きかったのは 5 本である．k（+1.91±0.73），ヘッドだけを選び直した qk（+2.10±0.62），提案手法の 3 本での qk 変化項（+3.76±1.24），v 変化項の 2 本（+9.90±2.40，+5.35±1.63）．
  • 事例の続きと予測対象の RMSE の順は，MSE の順と一致しない．RMSE が提案手法（1.283）より小さい 8 本（q，q 前項，k，v 前項 2 本，qk 前項 2 本，qkv 変化項）のうち，MSE の差が標準誤差の 2 倍を超えたのは k だけで，向きは正（提案手法より大きい）．
  • qkv の 3 つは，どれも提案手法との MSE の差が標準誤差の 2 倍の中だった．全体 +0.31±0.33，前項 −0.58±0.62，変化項 +0.56±0.31．事例の続きと予測対象の RMSE は 1.284，1.311，1.272 で，提案手法（1.283）との違いは 0.03 以下．
  • ランダムと提案手法の MSE の差は +0.46±0.84 ポイントで，標準誤差の中である．事例の続きと予測対象の RMSE は 1.592 と 1.283 で違う．
  • OT では，表のすべての点数（ランダムをふくむ）で MSE が提案手法より小さかった．提案手法に対する変化率は −0.7（qkv 全体）〜−11.4%（提案手法の 3 本での v 変化項）で，予測対象で選ぶと −33.3%．

次の一手

  • q と k で選んだ事例で，MSE が下がらない理由を調べる．事例の続きと予測対象の RMSE は，予測対象で選ぶ場合を除いて表で最も小さかったが，MSE は提案手法より大きかった．
  • 流していない 4 個（q 変化項，k 前項，k 変化項，v 全体）を流すかを決める．k 前項の上位 3 本の平均（+0.472）は，流した q 前項（+0.479）に次いで 4 番目だった．
  • ほかのデータセットの val で，qk 前項を提案手法と比べる．ETTh1 の val は，ヘッドの選び直しと評価の両方に使った．
  • test は，val で 1〜2 本に決めてから 1 回だけ流す．
条件

実験条件

  • データと指標：ETTh1（7 チャネル，train 12 か月，val 4 か月），履歴 512 時点，予測 64 時点，起点は val の中に 17 時点おき（チャネルあたり 166 本，計 1162 クエリ）．MSE・MAE は中央値の誤差をチャネルごとに train の標準偏差で割り，チャネルで平均する．モデルは Chronos-2（amazon/chronos-2）で重みは凍結．test は使っていない．
  • 共通の設定：候補はクエリごとに，起点より 96 時点以上前に終わる train の窓からランダムに 2048 件（どの点数も同じ seed で同じ候補）．上位 K=256 件を並列の行として入れ，P1 を隠す．
  • 前計算：train の 1 時点おきの窓すべて（チャネルあたり 8065 件）を，続きを入れた場合と隠した場合に 1 本ずつ流し，予測パッチ 4 列で，ヘッドの q，k，v を取り出して results/cache/ に保存する（q は今回から保存）．クエリは続きを隠して流す．v は，ヘッドごとに WO,h のグラム行列のコレスキー因子を掛けてから差の L2 ノルムを取る（WO,h を掛けた空間で測るのと同じ）．
  • 再現の確認：点数のコードを q，k，v の 15 個を共通に扱う形（codes/selection.py の candidate_terms と head_terms）に書き直した．提案手法の 3 本で，提案手法，qk 前項，qk 変化項，v 前項，v 変化項の 5 つの点数が選ぶ事例は，書き直す前と全起点で一致した．ヘッドの選び直しに使う順位相関も，前回までに測った点数では書き直す前と一致した（差 0）．
  • 名前の変更：前回までの --value-score kpre と kchange（q0·k̃j と q0·(kj − k̃j) の softmax）は，qkpre と qkchange に名前を変えた．結果のファイルも _vkpre → _vqkpre，_vkchange → _vqkchange に変えた．kpre と kchange は，いまは k の差の L2 ノルムの点数である．
