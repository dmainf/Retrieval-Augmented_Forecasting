共通セットを勾配で選ぶ試み：CLG と Parallel-CLG

全クエリに同じ事例セットを渡すとき，その中身を勾配で選べば良くなるかを試した． 結論は「ランダムに選ぶのとほぼ変わらず，クエリごとの文脈照合にも届かない」． 論文の筋は本ノートに移した．ここには手法と結果を残す．

1

何をしたか

CLG

CLG（Zhang et al., ACL Findings 2025）は，LLM の many-shot のために作られた事例の選び方である． 学習できる「潜在の事例」を入力に置いて学習し，各時点の勾配を例ごとに記録する． そして，勾配の平均が全データの平均に近くなる例を選ぶ． 「全データで学習したのと同じ動きを生む例は，事例としても良い」という考え方である．

式で書く．凍結したモデル pθ の入力に潜在 z を足し，例 q=(x,y) の正解の尤度が上がるように z だけを学習する． z0,…,zE は各エポック後の潜在である．

L(z;q) = −log⁡pθ(y∣z,x) , ze+1 = ze − η ∇z Eq∈DN [L(ze;q)]

Chronos-2 は尤度ではなく分位点を出すので，ここでは −log⁡pθ の代わりに分位点損失（学習時と同じ）を使う． この損失を使って，例 q の勾配の軌跡と，選ぶ集合を次のように定める．

G0:E(q) = [ ∇zL(z;q)|z=z0 ;…; ∇zL(z;q)|z=zE ] Dn* = arg⁡minDn⊂DN ‖ Eq∈DN [G0:E(q)] − Eq∈Dn [G0:E(q)] ‖ 2

選んだ理由は，全クエリ共通のセットを many-shot で選ぶために作られていること，集合として選ぶので似た例が重なりにくいこと， LLM の 128-shot でランダムより約 4% 良かったことである．

Parallel-CLG

元の CLG は潜在を入力の前に連結する．しかしこのノートでは事例を並列の行として渡すので， 連結の潜在から取った勾配は，推論で事例が読まれる経路と合わない． そこで潜在を，実在の事例と同じ並列の行に置いた（Parallel-CLG）．違いは潜在の置き場所だけである．

設定は次のとおり．CLG と Parallel-CLG は，潜在の置き場所以外をそろえた．

CLG と Parallel-CLG はランダムとほぼ同じ．勾配の平均から最も遠いセットは，はっきり悪い 小さいほど良い．括弧内はランダム（K=32 は 25 本，K=128・256 は 5 本の平均）との比で，マイナスならランダムより良い． Parallel-CLG はここでは L2（平均に合わせる）で選んだもの． Parallel-CLG の逆（勾配の平均から最も遠いセット）は K=128 で MSE 0.5314（+3.4%），MAE 0.4788（+2.1%）で，ランダムよりはっきり悪い． CLG と Parallel-CLG のランダムとの差は ±0.5% 以内で，K によって向きも変わり，一貫した優位はない．どの選び方でも MAE は参照なしより悪い．

CLG も Parallel-CLG も，ランダムとの差は ±0.5% 程度だった． 一方，勾配の平均から最も遠いセットを選ぶと，はっきり悪くなる．勾配で悪いセットは見分けられるが，良いセットは作れていない．

選び方：平均に合わせる（L2）か，向きで選ぶ（コサイン）か

コサインで MAE が良くなるのは Parallel-CLG だけ．CLG ではむしろ少し悪くなる 括弧内はランダム共通セット（K=32 は 25 本，K=128・256 は 5 本の平均）との比で，マイナスならランダムより良い． Parallel-CLG のコサインは，MAE が 3 つの K すべてでランダムより良い（−0.6%，−0.2%，−0.3%）． CLG のコサインは，MAE が 3 つの K すべてでランダムより 0.1〜0.3% 悪い．MSE はどの組み合わせもランダムと同程度． 差は小さく，ランダムの seed によるばらつきと同程度だが，3 つの K で向きがそろっている． この結果から，Parallel-CLG の既定の合わせ方をコサインにする（CLG は元論文どおり L2 のまま）．

コサインで選ぶと，Parallel-CLG だけ MAE がどの K でも少し良くなった．同じ選び方でも CLG では良くならない． 違いは潜在の置き場所だけなので，「選ぶ信号を推論の経路にそろえる」効果と言える．ただし差は小さい．

文脈照合が少ないときは共通セットを足すと良くなる．同じ行数なら文脈照合だけの方が良い val・全 7 チャネル．括弧内は同じ列の「共通セットなし」との比（文脈照合 0 の列では参照なしとの比）で，マイナスなら良い．太字は各指標の最良（参照なしを除く）． 共通セットのランダムは seed 0 の 1 本，Parallel-CLG は L2（平均に合わせる）で選んだもの． 文脈照合 8 件に共通セットを足すと MSE は 0.5186 から最大 0.5125（−1.2%，Parallel-CLG 32）まで下がるが，文脈照合 128 件では足すとわずかに悪くなる． 合計の行数をそろえると（例：文脈照合 32 件の 0.5120 と，共通 32＋文脈照合 8 件の 0.5125・0.5156），文脈照合だけの方が同じか良い． MAE は，どの組み合わせも参照なしに届かない．

文脈照合が少ないときは共通セットを足すと良くなるが，同じ行数なら文脈照合だけの方が良い．共通セットは補いにしかならない．

補足：学習した潜在そのものは効くか（OT）

Parallel-CLG で学習した潜在 8 本をそのまま事例にすると，train では MSE −8.4% と効くが，val では参照なしより悪い（+1.3%）． train で最適な事例ですら，val では通用しない．

3

なぜうまくいかなかったか

1件数が多いと，ランダムでも目的が満たされてしまう． 「平均の勾配に合わせる」という目的は，ランダムに選んでも件数が多いほど自然に満たされる．many-shot では工夫の余地が小さい
2全クエリに同じセットを渡すこと自体が不利． クエリごとに選べないので，同じ件数なら文脈照合に負ける．LLM と違い，計算を使い回せる利点もない
3train で良い事例が，val でも良いとは限らない． 勾配はすべて train の窓から取るので，時期による性質のずれに弱い
4勾配は「事例としての効き目」を直接は測っていない． 測っているのは「その窓を予測するとき何が欲しいか」で，「その窓を渡すと他がどれだけ良くなるか」ではない
残したこと

選ぶ信号を推論の経路（並列の行）にそろえると，MAE が少し良くなる．Parallel-CLG の発想そのものは支持された．
