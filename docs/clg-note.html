共通セットを勾配で選ぶ：CLG と Parallel-CLG の記録

全クエリ共通の many-shot セットの中身を，勾配マッチング（CLG；Zhang et al., ACL Findings 2025）と， その潜在を並列の行に置いた Parallel-CLG で選ぶ試みの記録である． 同じ件数ではクエリごとの文脈照合に届かず，論文の筋は本ノートの「並列による many-shot」に移した． 手法，結果，うまくいかなかった理由を残す．

1

手法と結果

共通セットの中身を原理的に選ぶ方法として，LLM の many-shot ICL のために提案された CLG（Curriculum Latent Gradient；Zhang et al., ACL Findings 2025）を出発点にする． ただし CLG は，事例を時間方向に連結する容れ物を前提にしている．並列の容れ物に合わせて作り直したものが，当初の提案手法だった Parallel-CLG である．

CLG とは

CLG の前提は「ICL に必要なデータと，ファインチューニングに必要なデータは似ている」という仮説である． 全訓練データで学習したときと同じ学習の動きを生む少数の例を選べば，それは事例としても良いはず，と考える． 手順は 3 段である．

例 q の勾配の軌跡と，選ぶ集合は次のとおりである（DN は全候補，Dn は選ぶ n 件）．

G0:E(q) = [ ∇ZL(Z;q)|Z=Z0 ;…; ∇ZL(Z;q)|Z=ZE ] Dn* = arg⁡minDn⊂DN ‖ Eq∈DN [G0:E(q)] − Eq∈Dn [G0:E(q)] ‖ 2

なぜ CLG を使うか

共通セット向け全クエリに使い回す 1 つのセットを選ぶための手法で，4〜128 件（一部 1024 件）の many-shot で評価されている． 既存の task-level の選び方（強化学習やベイズ的な選択）は数件の規模でしか試されていない
集合として選ぶ1 件ずつ点数をつけて上位を取るのではなく，選んだ集合の平均を全体に合わせる． 似た事例ばかりが重なる冗長さを自然に避けられる
モデルが使う信号似ているかどうかといった外から決めた指標ではなく，モデル自身の損失の勾配で選ぶ． 本ノートの 3 節で見たとおり，外から決めた類似度（文脈の近さ）は未来の近さとほとんど関係しない
LLM での実績128-shot で，ランダムな共通セットを平均約 4% 上回る（Llama3-70B，Qwen2.5-72B，9 データセット）． 選択そのものは数分で終わる

CLG の足りない点

CLG は潜在を入力の先頭に連結して学習する．元論文は注意の経路を論じていないが， 先頭の潜在が後ろのトークンに届く経路はトークン列に沿った自己注意だけであり，Chronos-2 でこれに当たるのは時間方向の注意（time attention）である， というのがこのノートの解釈である．LLM ではこれが事例の読まれ方そのものなので問題ない．しかしこのノートの容れ物では，事例は並列の行として渡され， 系列間の注意（group attention）を通して読まれる．

通り道がずれるCLG の勾配は「先頭に連結した事例から何を受け取りたいか」を表す． ところが推論では，事例は並列の行から読まれる．選ぶときの信号と，推論で事例が読まれる経路が一致しない
連結の経路は事例を読まない本ノートの 2 節で見たとおり，連結では実在の窓の未来はほとんど使われない（未来照合で並列 −18.7%，連結 −2.4%）． CLG は，推論では使わない経路の信号で選んでいることになる
1 本の系列に見える連結では潜在と履歴が 1 本につながり，正規化も時刻の扱いも共有される． 潜在が「参照する事例」なのか「履歴の続き」なのかが区別されないまま勾配が取られる

Parallel-CLG

そこで潜在を，実在の事例が入るのと同じ場所に置く．潜在 Z を K 本の「仮想の事例」とし， それぞれを並列の共変量の行として入力する．文脈部分は履歴の末尾 96 点の位置に，未来部分は予測する 64 点の位置に載る． 勾配は group attention を通ってクエリから潜在に戻るので， G0:E(q) は 「クエリ q が，並列の行から何を受け取りたいか」を表す．勾配の軌跡の作り方と選び方（上の 2 式）は CLG と同じで， 違うのは潜在の置き場所だけである．

Parallel-CLG を使う理由

通り道を揃える選ぶときの信号が，推論で事例が読まれるのと同じ経路（group attention）を通る． 「このクエリが並列の事例から何を受け取りたいか」をそのまま測れる
扱いを揃える潜在の行は，実在の事例と同じく行ごとに正規化され，文脈は履歴の末尾，未来は予測区間の上に置かれる． 潜在が履歴の続きと混ざらない
中身が読まれる経路本ノート 4 節の未来の入れ替え（E5）で，並列ではモデルが事例の文脈と未来の対応を使っていることを確かめた． その対応を読む経路の勾配で選ぶので，選んだ事例の中身が推論で活きることが期待できる
比較がきれいCLG との違いは潜在の置き場所だけである．CLG と Parallel-CLG を比べれば， 「信号の通り道を推論に揃えること」の効果だけを取り出せる

確かめること・主張しないこと

確かめること：Parallel-CLG がランダム共通セットを seed のばらつき（K=32 で ±0.5%）を明確に超えて上回るか．CLG を上回るか． MSE だけでなく MAE と QL も改善するか．val で K を決めてから test を出す．

主張しないこと：CLG の「ICL とファインチューニングに必要なデータは似ている」は元論文でも仮説であり，理論的な保証ではない． また Chronos-2 の並列では事例の中間表現がクエリごとに変わるため，共通セットでも LLM のような計算の使い回しは効かず， task-level だから軽い，とは言えない．

分かったこと

勾配には信号があるが，「全体の平均勾配に合わせる」という目的では many-shot でランダムを超えられない． 最も遠いセット（元論文の逆の選択）は K=128 で QL がランダムより 2.5% 悪く（参照なしより 3.4% 悪い），OT を除く 6 チャネルすべてでランダムより悪い．悪いセットは勾配で見分けられている． しかし，ランダムに選んだ n 件の平均勾配も，n が大きいほど全体の平均に近づく（ずれはおよそ 1/n）． many-shot では平均に合わせる目的がランダムでもほぼ満たされるため，選び方の差が出にくい． 「選ぶときの信号を推論の経路に揃える」こと（CLG と Parallel-CLG の違い）の効果も，この目的のままでは見えない．

合わせ方：平均との距離（L2）か，向きのそろい（コサイン）か

CLG は，選んだ窓の平均勾配と全体の平均勾配の L2 距離を小さくする．代わりに，各窓の勾配の軌跡と全体の平均勾配のコサイン類似度で並べ， 上から選ぶ方法も試した．コサインが大きい窓は「その窓で潜在を学習すると，平均的なクエリの損失も下がる」窓である （学習の各時点の勾配の内積を足す TracIn や，目標との勾配の類似度でデータを選ぶ LESS と同じ考え方）． 似た窓ばかり選ばれないよう，選んだ窓どうしの間隔に下限を設けた（K=32 で時間的に重ならない 15 本，K=128 で 4 本，K=256 で 2 本）． CLG と Parallel-CLG の両方で，L2 とコサインを比べた．

分かったこと

潜在を並列に置いたときだけ，勾配の向きで選ぶと分布の当たり具合が良くなる． 同じコサインで選んでも，CLG（潜在を連結）では MAE・QL がランダムより悪く，Parallel-CLG（潜在を並列）では 3 つの K すべてで良い． 両者の違いは潜在の置き場所だけなので，「選ぶときの信号を推論の経路に揃える」ことの効果が，初めて結果に現れた （Parallel-CLG のコサインは CLG のコサインより MAE が 0.4〜0.8%，QL が 0.5〜0.6% 良い）． ただし効果は小さく，MAE と QL はまだ参照なしに届かない．

分かったこと

共通の many-shot セットは，文脈照合の代わりではなく，文脈照合が少ないときの補いとして効く． 行数（計算量）をそろえると，クエリごとに選ぶ文脈照合の方が共通セットより良いか同等で，MSE の最良は文脈照合 128 件（0.5095）である． 共通セットを主張の中心に置くなら，文脈照合を超える選び方か，検索の索引が要らない・クエリの前に用意できるといった別の利点が必要になる．

合わせる先：train 全体か，直近の窓か

時期のずれへの対策として，合わせる先を train 全体の平均勾配から，val の直前（train の最後の 2 / 4 / 8 週間）に終わる窓の平均勾配に変えた． 窓の数は 30 / 61 / 122 本．選んだセットは val の全クエリで共通なので task-level のままである． 直近の平均勾配は train 全体の平均勾配と向きがかなり違い（OT でコサイン −0.03〜0.31），選ばれるセットもほぼ入れ替わる．

補足：学習した潜在そのものは val で効くか（OT）

OT は，どの共通セットでも参照なしより悪くなるチャネルである．Parallel-CLG で学習した潜在 8 本をそのまま事例として渡すと， train では MSE −8.4%，QL −3.6% まで改善するが，val では MSE +1.3%，QL +0.8% と参照なしより悪い． train の期間で最適化した「理想の事例」すら val で通用しないので，OT では実在の窓をどう選んでも参照なしを超えにくい． train（2016-07〜2017-06）と val（2017 年夏〜秋）の時期のずれが原因と考えられる．

実装上の注意：CLG（連結）の損失は，潜在込みで決まる正規化のまま測っている（連結が履歴と 1 本の系列に見えること自体が問題点という立場）． そのため train の損失は 2.75 から約 0.8 まで下がるが，予測の改善ではなく正規化の幅が広がった影響が大きい． また履歴の先頭が欠測の窓では，欠測が潜在の勾配に NaN として混ざるので，欠測の埋め草を取り除いてからつないでいる．

2

なぜうまくいかなかったか

CLG も Parallel-CLG も，同じ件数ではクエリごとの文脈照合に届かず，ランダムな共通セットとの差も ±0.5% 程度にとどまった． 結果から考えられる理由を，確からしい順に挙げる．どれも ETTh1 の val での観察からの推測で，切り分けの実験はしていないものを含む．

1．「全体の平均勾配に合わせる」目的は，many-shot ではランダムでもほぼ満たされる

CLG の目的は，選んだ n 件の平均勾配を全体の平均勾配に近づけることである．しかし，ランダムに選んだ n 件の平均も， n が大きいほど全体の平均に近づく（ずれはおよそ 1/n）． OT の K=128 では，全体の平均までの距離がランダム 0.046，Parallel-CLG 0.016 で，ランダムもすでに近い． 目的がほぼ満たされた状態からさらに詰めても，予測には差が出にくい． 逆に，最も遠いセット（逆の選択）ははっきり悪かった（K=128 で QL がランダムより 2.5% 悪い）． 勾配には「悪いセット」を見分ける信号があるが，「ランダムより良いセット」を作る余地が，この目的では残っていない． 元論文が 128-shot で差を出せたのは，NLP のデータの方が例ごとのばらつきが大きく，ランダムな部分集合が全体を代表しにくいためかもしれない．

2．共通セットという制約そのものが不利

同じ件数なら，クエリごとに選ぶ文脈照合の方が，どの共通セットよりも MSE で 0.7〜1.0% 良かった． 共通セットは全クエリに同じ事例を渡すので，1 つ 1 つのクエリに合わせられない． group attention は並んだ行の中から使う事例を選べるが，選べるのはセットに入っている事例だけで，ライブラリの中身が同じなら限界がある． さらに Chronos-2 の並列では，事例の行が各層でクエリを見るため，中間表現がクエリごとに変わる． LLM で共通セットが好まれる理由（共通部分を一度だけ計算して使い回せる）が，ここでは成り立たない． 精度でも計算でも共通セットを選ぶ理由が弱く，選び方を工夫する土台そのものが不利だった．

3．train で最適な事例が val で最適とは限らない（時期のずれ）

OT では，Parallel-CLG で学習した潜在 8 本をそのまま事例にすると，train では MSE −8.4% まで効くのに，val では参照なしより悪かった（+1.3%）． CLG 系の勾配はすべて train の窓から計算するので，選ばれるのは「train の期間で役に立つ事例」である． train（2016-07〜2017-06）と val（2017 年夏〜秋）で系列の性質がずれていると，その事例は val では役に立たない． 直近の窓に合わせる工夫は，数十本の平均がその数週間に特有の動きに引っ張られ，かえって悪化した．

4．勾配が測っているのは「事例として渡したときの効果」ではない

窓 q の勾配は，q をクエリにしたときの損失を潜在で微分したもので，「q を予測するとき，並列の行から何を受け取りたいか」を表す． 「q を事例として渡したら，ほかのクエリがどれだけ良くなるか」は測っていない． 両者を結びつけるのは「ICL とファインチューニングに必要なデータは似ている」という元論文の仮説だけで，時系列で成り立つかは確かめていない． また，潜在は推論の 128〜256 本に対して 8 本しか並べていないので，系列間の注意の分け合い方も推論と違う．

5．事例を渡すと分布が広がる問題を，選び方では解けない

どの選び方でも，事例を渡すと 80% 区間が広がりすぎ（的中率 0.83〜0.86，理想 0.80），MAE と QL は参照なしに届かなかった． いろいろな未来を持つ事例が並ぶと，モデルの予測分布もその分だけ広がると考えられる． Parallel-CLG をコサインで選ぶと広がりは少し抑えられたが，参照なしを超えるほどではない． これは選び方より，事例の渡し方（並列の行の読まれ方）に起因する可能性が高い．

それでも見えたこと

同じコサインで選んでも，潜在を連結した CLG では MAE・QL がランダムより悪く，潜在を並列に置いた Parallel-CLG では 3 つの K すべてで良かった． 両者の違いは潜在の置き場所だけなので，選ぶときの信号を推論の経路（group attention）に揃えると，分布の当たり具合が良くなる． 効果は小さい（0.1〜0.8%）が，Parallel-CLG の発想（推論と同じ経路で信号を取る）自体は支持された．
